# 商业分析模拟案例库

这是一个完全原创、完全合成、可以重复运行的商业分析案例库。

它不是对任何付费课程、线上实习、公司数据或答案的复制。公开仓库中的企业、供应商、订单、付款、实验对象、质量事件和管理建议均为虚构。

## 项目包含什么

| 案例 | 需要支持的决策 | 主要方法 | 故意设置的陷阱 |
|---|---|---|---|
| 供应链分群 | 不同供应商—运输关系应采用什么管理政策 | 确定性 K-means、轮廓系数、画像与政策映射 | 把分群误写成因果结论 |
| 会计数据整合 | 哪组季度营收、毛利、回款和应收数字可以发布 | 数据粒度、去重、引用完整性、对账、SQL | 多对多 Join 放大营收 |
| A/B 实验审计 | 新活动是否应该全面上线 | Wilson 区间、两比例检验、分层标准化 | 分组结构失衡导致辛普森悖论 |
| QA 指标排障 | 客户体验真的恶化，还是埋点与重试改变了指标 | 事件去重、工作流粒度、首轮与最终成功率 | 分母漂移与重复事件 |

最后一份季度管理报告将四个案例连接起来，但不会用一个总分掩盖互相冲突的证据。

## 一条最重要的原则

```text
先定义决策
→ 再定义分析单位
→ 再定义指标分子和分母
→ 再检查数据质量和可比性
→ 最后才计算和提出建议
```

## 为什么不复制旧课程材料

历史经历能够证明曾完成过虚拟商业分析任务，但它不能自动赋予公开原始题目、数据、截图或答案的权利。本项目只保留可公开证明的能力方向，然后从零设计：

- 新公司背景；
- 新数据生成规则；
- 新任务说明；
- 新代码；
- 新指标合同；
- 新测试；
- 新报告和审计机制。

因此这个仓库展示的是独立重建与分析能力，而不是转存课程文件。

## 四个案例最值得学习的内容

### 1. 供应链分群

- 标准化不同量纲的成本、交期、服务、质量与波动字段；
- 比较多个 K，而不是凭感觉指定分群数；
- 把分群转化为差异化管理动作；
- 明确分群是描述性工具，不证明某项政策会产生因果效果。

### 2. 会计数据整合

- 订单行、发票、付款和退货处于不同粒度；
- 多个一对多表不能在原始层直接相连后求和；
- 付款需要按 `payment_id` 去重；
- 找不到发票的付款和找不到订单行的退货必须进入隔离区；
- 现金回款不等于收入，发票金额也不等于净营收。

### 3. A/B 实验

- 处理组在每个预先定义的分层中都更好；
- 但由于处理组和对照组的渠道构成严重不同，汇总结果方向相反；
- 系统同时展示朴素汇总结果和分层标准化结果；
- 正确结论不是挑选更顺眼的结果，而是重新做分层随机，并事前定义目标估计量。

### 4. QA 指标

- 原始失败事件数可以衡量系统负荷，但不等于客户最终失败率；
- 重试成功应计入恢复能力；
- 重复埋点必须先去重；
- 首次成功率、最终成功率、重试率和客户影响率需要分别报告；
- 指标突然变化时，要先检查分母、采集和口径，再写业务叙事。

## 公开边界

仓库没有真实：

- 公司或客户资料；
- 员工、候选人或供应商资料；
- 课程数据和答案；
- 邮箱、电话和账号；
- 云端 Token 与配置；
- 经营结果和雇佣关系。

成熟度为：`fixture-method-and-integrity validated`。这表示合成数据、方法、代码和完整性验证通过，不表示已经在真实企业生产环境中验证。
